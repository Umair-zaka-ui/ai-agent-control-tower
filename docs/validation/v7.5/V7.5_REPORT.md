## A. Executive verdict

One cloud discovery adapter — **`AWS_BEDROCK_AGENTS`** (Agents for Amazon Bedrock) — was built on the unchanged
5.2 `DiscoveryAdapter` contract, discovery-plane-only, read-only, `GovernedHttpClient`-only, with no migration,
table, route, dependency or M1–M5 behaviour change. Its containment is inherited and asserted structurally

guard update. F6-1 is explicitly **not** addressed; cloud-discovered agents inherit it by design for V8.

**What could not be done:** no read-only cloud credential could be established (no cloud account is available

## C. Chosen cloud and why

**AWS — Agents for Amazon Bedrock.** Cheapest scoped read-only sandbox: free-tier account, `ListAgents` is free,
a one-action custom IAM policy, free budget alerts. It is the provider's first-class *agent* primitive, so the
agent-definition filter is precise by construction. One signed HTTPS request per page — no OAuth token exchange
with a second host (Azure AI Foundry / GCP Vertex Agent Engine both need one). Every wire fact was taken from
public AWS reference documentation and botocore's `bedrock-agent/2023-06-05` service model (`POST /agents/`,
`AgentSummary`, endpoint `bedrock-agent.<region>.amazonaws.com`, signing name `bedrock`). Alternatives (boto3,
Azure, GCP, Cloud Control API, account-wide inventory) are weighed in ADR-0024.

## D. The agent-definition filter — what counts, what is excluded, and why

`is_bedrock_agent(summary)`, pure and fixed in code:

- **Counts as an AI agent:** an element of `ListAgents.agentSummaries` with the API's required identity —
  `agentId` matching `^[0-9a-zA-Z]{10}$` and a non-empty `agentName` — whose `agentStatus` is not `DELETING`.
  `CREATING / PREPARING / PREPARED / NOT_PREPARED / FAILED / VERSIONING / UPDATING` (and absent) are included:
  a defined-but-inoperable agent is still an agent in the estate; status is carried as metadata.
- **Excluded:** `DELETING` (AWS says it is leaving; discovering it would create-then-stale). And *everything
  that is not an agent summary* — foundation models, knowledge bases, flows, prompts, guardrails, **agent
  aliases and versions** (deployment pointers), Lambda, ECS, EC2, SageMaker, the rest of the cloud. None of
  these is ever listed because the adapter calls only `ListAgents`; a malformed or foreign-shaped element
  inside a page is dropped, so a poisoned page cannot inflate the inventory.
- **Why conservative:** over-broad discovery ("every function is an agent") is a defect in the brief's own
  terms; the filter admits only the construct AWS itself defines as an agent, and is not operator-tunable.

Tested with every status, 17 non-agent shapes, and a mixed live page (only the 2 real agents observed).

## F. Adapter behaviour

Flow: source(region, encrypted secret) → `run_source` → **fetch with no session in scope** (`ListAgents`,
signed, paginated on `nextToken`, filtered, bounded 200×100) → normalize (`bedrock-agent:<region>:<agentId>`,
`origin_provider=AWS_BEDROCK_AGENTS`, confidence 1.00 constant) → scrubbed append-only observations →
CREATE `EXTERNAL`/`DISCOVERED` | LINK | FLAG → staleness → run finished.

- **No lock across the cloud call:** structural (signature) and behavioural (a concurrent `FOR UPDATE` on the
  source row commits in < 2 s while the cloud response is held open).
- **Idempotent:** 7 created → 7 linked → 7 linked; 21 append-only observations; 7 agents.
- **Staleness:** removed asset → one `STALE_AGENT` finding, no state change, no repeat per miss, resolved on
  reappearance. **Outage** (refused connection, 403) → `FAILED` run, nothing touched, **no** staleness — absence
  of evidence is not evidence of absence; the durable record is the run row.
- **Rate limit / partial:** later-page 429 → `PARTIAL` with the page token as checkpoint → next sweep resumes
  from it. An expired resumption token (400) → one fresh sweep, never a stuck source.
- **Read-only:** one call site, `POST /agents` (AWS's documented list operation), one IAM action; the mock
  records and refuses any other verb/path and saw none.

## G. Containment proof (structural unless noted)

- **GovernedHttpClient-only:** exact `app.*` import set `{discovery.adapters.base, discovery.adapters.registry,
  identity.errors, integration.base, integration.sdk}`; no `boto3/botocore/httpx/requests/urllib.request/
  urllib3/socket/aiohttp/http.client/ssl`; no `boto*` binding; exactly one `.request(` call site.
- **Discovery-plane-only:** no import from `app.threat/bridge/posture/graph/runtime/models/observability/
  scheduler/command_center/assurance`; no new table/route/migration (head stays `0061`).
- **Read-only:** method constant `POST`, path `/agents/`, `REQUIRED_IAM_ACTIONS == ("bedrock:ListAgents",)`,
  no mutating verb or `bedrock:(Get|Create|Delete|Update|Prepare|Invoke|…)` literal; behaviourally zero non-list
  calls across every integration test.
- **Tenant-scoped (B):** agents only in the owning tenant; the other tenant gets 404 on read/run and sees none.
- **No cloud credential in observations (B):** access key id, secret and session token absent from
  observations, run errors, audit meta, the source read; a `sk-…`/`AKIA…`-shaped description is
  `***REDACTED***` (scrubbed by shape); `encrypted_secret` is ciphertext; hint is 4 chars; plaintext `config`
  is credential-free by schema. No AWS error body is ever recorded.
- **Host derivation:** region pattern-validated (6 hostile forms → 422); `endpoint_url` only `https://
  *.amazonaws.com` or a declared local host, origin-only; no `allowed_hosts` key accepted; plaintext only with
  declared local hosts; offline `evaluate()` denies any other host and plaintext-to-AWS.
- **Signing over the real wire bytes:** body/content-type/host/path mirrors pinned against `httpx.Request` and
  `_build_target_url`; known answers equal botocore's `SigV4Auth` (IAM example, Bedrock POST, Bedrock POST +
  session token); the mock recomputes SigV4 from the request as received — 0 signature failures.

## H. F6-1 — explicitly NOT addressed; cloud agents inherit it by design

The adapter emits observations only. It writes nothing the six threat rules read, and imports nothing from
`app.threat` or `app.bridge` (asserted). A Bedrock agent discovered by it is an ordinary `EXTERNAL`/`DISCOVERED`
agent; if it is later registered and gateway-enforced, its denials will land in `external_gateway_calls` and
produce zero threat findings — exactly F6-1 as V6 found and V7 felt. That is **correct** for this phase: F6-1
is an M6 product decision with its own architecture reasoning, and V8 observing the inheritance on
cloud-discovered agents is useful evidence, not a defect in this adapter.

## P. V8 readiness — the adapter V8 will red-team, and what V8 should attack

V8 gets `AWS_BEDROCK_AGENTS` in the wrapper against a hostile Bedrock-shaped source (the V5 `hostile_registry`
pattern, now speaking `ListAgents`). Attack surface, in priority order:

1. **Hostile inventory:** poisoned `agentSummaries` (non-agent shapes, malformed ids, oversized `agentName`/
   `description`, secret-shaped descriptions), `DELETING` flip-flops, disappear/reappear flapping, replay of stale
   pages, identifier collisions across two regional sources, NATIVE-collision spoofing, duplicate ids within a page.
2. **Pagination games:** never-ending `nextToken`, token loops, `maxResults` ignored, absolute-bound pressure,
   throttling storms, `Retry-After` abuse — and F7.5-1 (partial-sweep staleness) under these.
3. **Egress/host confusion:** `endpoint_url` lookalikes (`amazonaws.com.evil`), plaintext downgrade attempts,
   redirects from the source (re-validated by the executor), response-size bombs (1 MiB cap), config smuggling.
4. **Credential handling:** attempts to make the adapter echo the credential (crafted 403 bodies, SigV4 error
   text), `secret_hint` leakage, audit-meta leakage, session-token handling, malformed-secret paths.
5. **Tenant and reconciliation:** cross-tenant source, hostile source causing unowned rows (F5-1 by design),
   confidence constant, no silent merge under races (M5.2-AC-10).
6. **The plane boundary as observation:** cloud-discovered agents registered and gateway-enforced should
   produce enforcement without findings — V8 should *measure* the F6-1 inheritance on cloud agents, not fix it.
7. **T5 (cloud privileges) must be built, not inherited** — V7 §R point 4 stands.

**Review conditions before V8 authorization:** (1) the exception scope (§L) and ADR-0024 accepted; (2) a first
live read-only sandbox run with the documented one-action policy (routing + signing confirmation) — or an
explicit decision to proceed to V8 on the mock-verified adapter and defer live validation.
